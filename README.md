# Танковые бои

## Сборка и запуск

Команды выполняются из каталога `IZ1`:

```bash
cmake -S . -B build
cmake --build build
./build/tanks
```

Без настроек запускается пример: поле 12×8, по два танка сторон A и B.
Другой сценарий можно выбрать из папки `data`:

```bash
./build/tanks --config data/demo.txt --seed 24 --delay 200 --log battle.log
./build/tanks --config data/conflict.txt --limit 0
./build/tanks --help
```

- `--config`: файл исходных данных.
- `--seed`: число для повторения случайных результатов боя.
- `--delay`: задержка между шагами в миллисекундах.
- `--limit`: максимальное число шагов; 0 означает работу без ограничения.
- `--log`: файл итогов, по умолчанию `battle.log`.

Настройки запуска заменяют значения из файла. На экране показаны события,
карта и итоги. В журнал записываются причина завершения, число шагов, потери,
выстрелы и попадания. При новом запуске журнал перезаписывается.

## Правила

- Координаты `(x, y)` начинаются с нуля в левом верхнем углу. Обозначения:
  `.` свободная клетка, `#` препятствие, `A`/`B` танки сторон, `X` обломки.
  Прочность и координаты каждого танка показаны под картой.
- При `hold` танк остаётся на месте. При `advance` приближается к ближайшему
  противнику до дальности стрельбы, двигаясь на одну свободную соседнюю клетку.
  Занятая в начале шага клетка недоступна. Если несколько танков выбирают
  одну клетку, все остаются на месте.
- Танк может выстрелить один раз за шаг по ближайшему противнику в пределах дальности.
  При равном расстоянии выбирается меньший номер. Стрельба навесная,
  препятствия её не блокируют. `accuracy` задаёт точность в процентах,
  `flight` число шагов полёта. При `flight=1` выстрел первого шага долетает на втором.
- Снаряд направлен в выбранную клетку. Точное попадание снимает 1 единицу
  прочности у находящегося там танка, даже союзного. При нулевой прочности
  остаются обломки, мешающие движению. Выпущенные снаряды продолжают полёт
  после уничтожения стрелявшего танка, пока бой не завершён.

В одном общем цикле сначала обе стороны выбирают действия по одному состоянию
поля. Затем выполняются выстрелы, решаются споры за клетки и перемещаются танки.
После прилёта снарядов весь урон применяется одновременно. В конце показывается
поле и проверяется завершение.

Бой заканчивается при уничтожении одной или обеих сторон либо по ограничению
шагов. Его можно прервать через Ctrl+C или сигнал SIGTERM. При любом завершении
записываются итоги и закрывается журнал. При `--limit 0` бой может продолжаться
бесконечно, например в `data/conflict.txt`. На ограничении шагов победитель
не назначается. После завершения оставшиеся снаряды больше не обрабатываются.

## Формат сценария

```text
field 5 2
limit 20
accuracy 100
flight 1
seed 24
delay 200
team A advance
team B hold
map
.....
..#..
tank A 1 0 0 3 4
tank B 1 4 0 3 4
```

После `map` идут строки поля заданной высоты и ширины из символов `.` и `#`.
После карты: `tank <A|B> <номер> <x> <y> <прочность> <дальность>`.
Номера уникальны внутри стороны. Вне карты допустимы пустые строки и
комментарии после `#`. Обязательны `field` и `map`.

В `data` находятся тестовые примеры. Для их проверки:

```bash
bash tests/run_tests.sh ./build/tanks
```

## Использование ИИ

Первый промпт: «Напиши код по следующему устройству программы. Использую C, один общий цикл без дополнительных потоков.
В `main.c` будут запуск и завершение, в `config.c` чтение исходных данных,
в `battle.c` расчёт боя, в `output.c` карта и запись итогов. Танки и снаряды
хранятся в массивах структур. Сначала обе стороны выбирают действия по одному
состоянию поля, затем выполняются выстрелы, решаются споры за клетки,
применяются перемещения и одновременно учитывается урон. Для файлов используй
дескрипторы, для вывода `dprintf`. При Ctrl+C нужно сохранить итоги и закрыть
файл. Перед написанием кода ознакомься с условием задания, предложи изменения по решению, согласуй со мной, только после этого приступай к написанию кода».

Дальше ИИ написал код по заданному устройству программы
и предложил проверку одновременного уничтожения танков. Я внимательно ознакомился со всем написанным кодом, задал уточняющие вопросы. После согласовал
проверку и уточнил, что весь урон нужно сначала собрать, а затем применить
ко всем танкам, чтобы результат не зависел от порядка обхода. После проверки
я исправил замеченные ошибки. Отдельные запросы к ИИ помогли
автоматизировать запуск примеров и сравнение результатов.
